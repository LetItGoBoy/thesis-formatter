# 题库设计规则

## 题目定位

关卡测试不是传统考试，而是确认学生是否理解“剧情事件背后的数据结构问题”。

每个小节 3 到 5 道题即可。题目要短、具体、和剧情任务相关。

## 每关题型比例

推荐每关 4 题：

1. 概念理解题
2. 场景判断题
3. 操作过程题
4. 误区辨析题

需要代码训练时，可替换为：

5. 伪代码或代码阅读题

## 题型说明

### 概念理解题

检查学生是否理解概念本质。

示例：

> 在“线性表街区”中，任务节点之间最重要的关系是什么？

答案方向：一对一的前后关系。

### 场景判断题

检查学生能否判断某种结构适合什么问题。

示例：

> 如果系统需要频繁访问第 100 个任务，但很少插入删除，应该优先考虑哪种存储方式？

答案方向：顺序表。

### 操作过程题

检查学生是否理解结构操作。

示例：

> 在链表中删除一个节点时，关键操作是什么？

答案方向：改变前驱节点的指针指向。

### 误区辨析题

检查常见错误。

示例：

> “链表一定比顺序表高级，所以所有场景都应该用链表。”这句话对吗？

答案方向：错误，结构选择取决于访问、插入、删除等操作需求。

### 伪代码或代码阅读题

用于高阶关卡，帮助学生从故事过渡到代码能力。

示例：

```c
while (p != NULL) {
    p = p->next;
}
```

问题：这段代码对应链表中的什么操作？

答案方向：遍历链表。

## 题目写作原则

- 题干不要长
- 每题只考一个点
- 选项要有真实迷惑性
- 错误选项尽量来自学生常见误区
- 解析必须回到剧情和知识点

## 答题反馈模板

答对：

```text
正确。你已经识别出这个结构解决的核心问题：{能力说明}。
```

答错：

```text
还差一点。这里的关键不是 {错误理解}，而是 {正确原理}。回到剧情里，主角需要解决的是 {场景问题}。
```

## 后台数据字段

教师后台需要记录：

- 学生 ID
- 课程 ID
- 章节 ID
- 关卡 ID
- 题目 ID
- 答案
- 是否正确
- 用时
- 重试次数
- 当前技能标签
- 错题知识点

第一版后台重点看：

- 哪一关通过率低
- 哪个知识点错误率高
- 哪些学生卡关
- 哪些题需要重写

## 第一章题目样例

### 关卡 1-1：任务为什么要排成线

题 1：线性表最核心的逻辑特征是什么？

- A. 所有数据都必须连续存储
- B. 数据之间存在明确的一对一前后关系
- C. 数据只能从尾部删除
- D. 数据必须按大小排序

正确答案：B

解析：线性表强调逻辑上的前后关系，不等于一定连续存储。

题 2：栈城任务清单出现“第 3 个任务后面直接跳到第 9 个任务”，更像是什么问题？

- A. 节点关系断裂
- B. 排序算法过慢
- C. 权限层级过深
- D. 图路径权值过大

正确答案：A

解析：任务清单的前后关系被破坏，对应线性结构中的节点连接异常。

### 关卡 1-2：顺序表

题 1：顺序表适合快速完成哪类操作？

- A. 已知位置的访问
- B. 在头部频繁插入
- C. 删除任意节点不移动元素
- D. 动态扩展无限节点

正确答案：A

解析：顺序表连续存储，可以通过下标快速定位。

### 关卡 1-3：链表

题 1：链表中每个节点除了保存数据，通常还需要保存什么？

- A. 下标
- B. 指向下一个节点的指针
- C. 排序结果
- D. 树的高度

正确答案：B

解析：链表依靠指针把节点连接起来。
