# 《雾港档案 · SQL 探案集》故事圣经

## 项目定位

《雾港档案》是「数据库原理」课程的 SQL 侦探推理游戏 IP。**季播单元剧**：8 个独立案件，每案教一组知识点，由一条主线反派「校对者 ROLLBACK」串起来。

它不把 SQL 当语法来背，而是让学生扮演查档侦探：每条线索都要写一句真实 SQL 去数据库里查，逐层缩小嫌疑范围，最后指认真凶。破案的过程，就是关系查询的过程。

核心理念：

> 侦探破案的循环——搜证 → 查询 → 求交 → 锁定真凶——本身就是关系数据库查询。

技术形态：浏览器内置 SQLite（sql.js / WASM），纯前端运行，无后端、无登录、无存档。学生写的每一句 SQL 都真实执行、即时反馈。

## 世界观与主线

雾港，一座常年浸在海雾里的港口城市。市民档案、打卡、车辆、账目都沉淀在「城市档案数据库」里。一个化名 **校对者（ROLLBACK）** 的人正在悄悄篡改这座档案库——制造混乱、掩盖痕迹。玩家每破一案，就离 TA 更近一步，终章揭穿 TA 是档案局内部握有最高数据库权限的人。

## 设计原则：让概念成为破案的机制

蛛丝马迹藏在**数据本身的特征**里，必须用对应的 SQL 概念才能发现：外连接的 `NULL`=没有记录=可疑；主键重复=伪造身份；外键孤儿=假记录；冗余字段不一致=改了一处忘改另一处；事务日志的中间状态=案发瞬间的真实快照。

## 已实现案件详情

### 第 1 案《后巷的打卡记录》

深夜命案，两条独立线索（健身房打卡 / 车牌含 X7）。**6 关层层递进**：浏览全表 → WHERE 单条件 → WHERE 多条件 AND → 按日期筛选 → LIKE 模糊匹配 → JOIN 求交，锁定真凶**高金**。4 张表：crime_scene_report、people、gym_checkin、cars。

### 第 2 案《高频的影子》

五起连环夜盗，每夜路过的人都不同。**6 关层层递进**：聚合(COUNT/MAX/MIN/AVG) → ORDER BY 排序 → GROUP BY 按区分组 → GROUP BY 按人分组 → HAVING 过滤高频 → HAVING+JOIN 锁定五夜全勤者，真凶是夜班保安**钱伟**。3 张表：people、burglary、sightings。

### 第 3 案《错综的关系网》

古董行老板被绑架，内部人作案。**6 关层层递进**：WHERE 读报告 → INNER JOIN 查受害人 → 自连接揭开汇报关系网 → LEFT JOIN 拼出全员不在场证明 → IS NULL 找出没有证明的人 → 综合（无证明 + 直接向老板汇报）锁定内鬼**苏晴**。3 张表：crime_report、staff（自参照 manager_id）、alibi。蛛丝马迹：**外连接里的 NULL = 没有不在场证明 = 嫌疑**。

> 设计约定：**每案至少 6 关**，难度阶梯式上升——前面关卡铺垫单个概念，后面关卡组合运用、收窄到唯一真凶。

## 关卡结构（沿用霓虹栈城模板）

剧情开场 → 概念出现 → 写 SQL 查证 → 关卡校验（命中关键行即过）→ 推进主线。卡住有文字提示，再卡可展开参考答案，降低劝退。

## 工程落点

```
frontend/app/quest/database/page.tsx          # 季度 hub（8 案列表）
frontend/app/quest/database/[caseId]/page.tsx # 单案件路由
frontend/components/CaseRunner.tsx             # 案件运行器（通用 UI）
frontend/components/SqlConsole.tsx             # SQL 编辑器 + 结果表
frontend/lib/sqljs.ts                          # sql.js 浏览器内建库封装
frontend/lib/db-detective.ts                   # 类型 + 通用校验工具 + 案件接口
frontend/lib/cases/                            # 各案件（每案一个文件）+ 注册表
frontend/public/sql/sql-wasm.wasm              # 自托管 WASM
```

入口：课程空间页「数据库原理」卡片 → `/quest/database` → 选案件。
